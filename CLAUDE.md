# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
pip install -r requirements.txt

# Run the app (default port 8501)
streamlit run nfl_replay_app.py

# Run with CORS/XSRF disabled (matches devcontainer config)
streamlit run nfl_replay_app.py --server.enableCORS false --server.enableXsrfProtection false
```

There is no test suite or linter. These scripts check the data paths against published data (each takes a season and an optional local parquet path):

```bash
python tools/validate_models.py 2025         # nflfastr_models.py vs published ep/epa/wp
python tools/validate_text_parser.py 2025    # gamebook-text parser vs nflverse columns
python tools/validate_live_pipeline.py 2025  # live derivations + models vs official
python tools/validate_espn_adapter.py 2025   # ESPN-shaped JSON round trip
python tools/build_fg_table.py 2018 2025     # rebuild models/fg_make_prob.csv
python tools/build_xrush_table.py NFL 2019 2025  # rebuild one league's rows of models/xrush_yards.csv (CFB 2023 2025)
python tools/validate_game_management.py 2025 [path] [n]  # next_snap() / three_and_out() / plays_left() vs what followed
python tools/validate_cfb_adapter.py 2026     # cfb_feed.to_pbp vs college final scores, ESPN team box + player box (defense)
python tools/validate_cfb_live.py 2026 [path] [n]  # live college path on ESPN JSON rebuilt from published games
python tools/validate_matchup.py 2025 [path] [first_week]  # Matchup page's Proj. and winner picks vs the games that followed
python tools/validate_injuries.py 2016 2025 [first_week]  # lineup changes vs Proj.'s misses; prints LINEUP_EFFECTS (VALIDATE_CACHE=dir keeps each season)
```

Dependencies: pandas 2.x (`<3`). NFL data comes through `nflreadpy`, nflverse's successor to `nfl_data_py` (whose last release pins pandas and numpy < 2). `sportsdataverse` processes live college games and needs pandas 2.

## Architecture

Python 3.11. The app covers the NFL and college football. A sidebar **League** radio picks a `League` object, and nothing else in the page branches on the league: both leagues produce play-by-play in the same nflfastR column layout (`PBP_COLS`).

- `nfl_replay_app.py`: the replay page (the app's entrypoint): sidebar, play cursor state and the sections, top to bottom. No data loading or stat logic of its own. The file name is kept so deployments don't need reconfiguring.

Tabs: **Teams** (`season_team_table()` offense or defense-allowed, column groups `TEAM_VIEWS`, sorted best first by rank), **Team** (`style_team_season()` cards with "5th of 32" ranks, **Schedule**: `team_schedule()`, one row per game with the final score from the whole game and the offense's and defense-allowed EPA/play (`game_epa()`, scrimmage plays) over the situation-filtered plays of both offenses, as played, colored by percentile among the selection's team-games, Result green for a win and red for a loss, then the games still to play from `league.upcoming()` (kickoff date, no EPA), `style_team_schedule()`; `situational_table(pbp, [team, None])` with the league column, tendencies vs `leagues.season_tendencies()`, leaders, then **Snap counts**: `team_snaps()` over the team's selected games, whole games so only weeks / games / venue apply, with a **Snap % by week** expander (collapsed; Offense / Defense / Special teams radio, `weekly_snaps()`: PFR's share per player and week plus Total, `style_weekly_snaps()`), and **Injury report**: the team's latest week, `injury_report()` + `availability_summary()`; both from `league.availability()`, a caption where the league has none) and **Players** (league-wide `season_players()` / `season_defenders()` with a minimum volume, default `PLAYER_MIN_PLAYS` × games), then a **Methodology** section that closes the page (its numbers are read from the `replay_core` constants). All Streamlit caching lives here, including `stat_baselines()` / `situational_baselines()` / `line_baselines()` / `player_baselines()` / `tendency_baselines()`.
- `replay_core.py`: the league-neutral logic, no Streamlit: `PBP_COLS`, `play_timeline()` and the cursor functions, `period_label()`, every stat builder (boxscore, team stats, situational success, line play, tendencies, leaders, drives, scoring, WPA) and the percentile math (`stat_distributions()`, `situational_distributions()`, `line_play_distributions()`, `player_distributions()` over `BASELINE_COLS`). - `live_feed.py`: ESPN summary JSON → the same nflfastR column layout (`PBP_COLS`). `parse_play_text()` reads the NFL gamebook text the way nflfastR does: play type, players, yards, results, tacklers, sacks, INTs, pass defenses, QB hits, forced fumbles and direction (`run_location`/`run_gap`, `pass_length`/`pass_location`); on a pass or run a penalty wiped out (`no_play`) it names the passer, rusher and receiver from the text before the flag (`_nullified_names()`), as nflverse's `passer`/`rusher`/`receiver` do. `espn_to_base()` splits a try ESPN folded into the touchdown's text at the try's start (`_split_try()`), so a flag or injury note in between stays with the touchdown, and the touchdown row carries only its own 6 points. Drive numbers come from possession changes (`_possession_drives()`, nflfastR's fixed_drive rules), not ESPN's drive grouping, which lags after turnovers mid-game. `add_derived_columns()` derives the rest: clock seconds, pre-play score differential, timeouts left (challenge timeouts included), first downs, `td_team`.
- `game_summary.py`: the AI game summary agent. The app builds a `GameContext` from its own stat functions run on `revealed`: boxscore, scoring timeline, team stats with `stat_percentiles()`, situational success, drive chart, top WPA plays, explosive plays and player leaders. `summarize()` sends a text snapshot (scoreboard, offense table with percentiles, a derived defense-allowed table, the Line play table with percentiles: `line_table()`, from `GameContext.line_play` / `line_pct`, `stat_percentiles(..., LINE_LOWER_IS_BETTER)`; and the all-downs Tendencies: `tendency_table()`, built from `revealed` with `GameContext.run_gaps` and the league's `tendency_baselines`) and runs a manual tool loop of up to `MAX_TURNS`. The tools are key plays by kind, drives, one drive's plays, offensive splits, situational success, tendencies on early/late/all downs and player leaders. It calls any Anthropic-compatible Messages endpoint. `configured_providers()` lists the ones that have a key: Kimi (Moonshot `/anthropic`, Bearer auth, default) and Claude. Only Claude models get `output_config.effort`, `strict` tools, prompt caching and the `fallbacks: "default"` beta. It makes no Streamlit calls, which lets the page run it on a worker thread: `submit()` hands it to a module-level `ThreadPoolExecutor` and returns a Future plus a `Progress` (current `status`, model `calls`, `steps` done) that `summarize()` updates as it goes; `describe_lookup()` turns each tool call into a line like "Looking at ALA turnovers". The Matchup page's preview is `preview()` (`submit_preview()` on the same pool): one call, no tools, `MATCHUP_PROMPT` with a `MatchupContext` (both `matchup_table()`s and `situational_matchup()`s, as text through `matchup_rows()` / `situational_rows()`, plus `names` (the teams' names, which the prose uses; the tables stay abbreviated), each team's season leaders with their Status, both injury reports by player and by unit, the betting line and the selection); about 150–220 words, only the given numbers and reports, no score prediction; it weighs starters who are Out or Doubtful by the matchup their unit is in and never brings up injuries the reports don't list. `_call()` (the API's errors as `SummaryError`s) and `_final_text()` are shared with `summarize()`.
- `cfb_feed.py`: college football from sportsdataverse's `espn_cfb_pbp` release (ESPN's feed with sportsdataverse-py's college EP/WP models, rebuilt about daily, 2004 onward), plus its schedules and team info. Only `RAW_COLS` are read: the release also has final scores, drive results, `lead_*` and after-play columns, which would spoil. `to_pbp()` maps to `PBP_COLS` the way `live_feed` builds the NFL layout: receiving team on kickoffs, the try split off the touchdown row (it's on the same row in ESPN's college feed), END QUARTER/END OVERTIME/END GAME rows, drives from possession changes. It also repairs the feed: rows listed after a later period go back into their own (`_relocate_late_rows`), scores keep the longest never-decreasing chain (`_clean_scores`; some rows carry a stale score or even the final score mid-game), and isolated clock spikes are dropped. Overtime rows get no clock (college OT is untimed). Defenders: most games since late 2025 have NCAA stat-crew text (`(08:47) Shotgun #7 A.Powell rush ... to the NDSU09 (#51 G.Sell; #9 K.Ford Jr)`), told apart from the older text by its jersey numbers (`_CREW`; the leading clock is missing on some rows, more often mid-game), and `_crew_columns()` reads tacklers (the parentheses after the ball carrier's spot, before any turnover, return, flag or review note), QB hurries, pass breakups, interceptors and fumble forcers from it, into nflfastR's tackle/sack/TFL/pass-defense/forced-fumble columns plus `half_tfl_*` and `qb_hurry_1..3_player_name`. College credit: one tackler is solo, two are an assist each; a shared sack or TFL is a half each; the sacker also gets the tackle. On those rows the text's names replace the feed's (and a game's other rows get `crew_spelling()`), so each player has one spelling. Older text names no tacklers; `missing_leader_stats()` then drops Tackles/TFL/Hurries, and the feed has no QB hits at all. Live games: `fetch_summary()` reads ESPN's college summary and `live_raw()` runs it through sportsdataverse-py's `CFBPlayProcess` (the pipeline that builds the release, so its rows have the release's columns and `to_pbp()` maps them unchanged; the one rename is `pos_team` → `pos_team_id`). It runs with `join_participants=False` (sportsdataverse's player-id lookup is dozens of ESPN requests) and no 4th-down/two-point models, so only the spread can hit the network (ESPN's odds endpoint, when the summary has no pickcenter). Without the player-id lookup, sportsdataverse's text parsing credits most stat-crew touchdown passes to "TEAM", so `_text_offense_names()` reads the passer, rusher and receiver from the stat-crew text instead and gives a crew game's other rows `crew_spelling()` (published games keep the release's id-based full names). `to_pbp()` blanks "TEAM" player names (team plays), as nflfastR does. The feed names few players of a pass or run a penalty wiped out, so `_nullified_names()` reads them from the text before the flag, among the players the offense's real plays in the game name, in any of the texts' spellings (`_spellings()`: full, "L.Marble", "Marble,Luke", any case; 98% of 2025's). Direction comes from stat-crew text only (`rush middle`, `pass incomplete short left`): `run_location` and `pass_length`/`pass_location`, never `run_gap`; interceptions name none. `list_games()` adds schedule games that kick off by today, have an FBS team and aren't published as `source="live"`; `team_ids()` fills the schedule's blank abbreviations for upcoming games from published plays, then team info. `upcoming_games()` lists games with an FBS team that kick off today or later and aren't finished, for the Matchup page (`_schedule_rows()` builds rows for it and `_live_games()`, `_labelled()` labels both lists). No Streamlit calls.
- `nflfastr_models.py`: nflfastR's own EP and WP xgboost models. They are extracted from `nflverse/fastrmodels` `.rda` files, downloaded once to `~/.cache/nfl_replays_pbp`. The module also ports nflfastR's EP/EPA/WP feature prep. The field-goal GAM can't run in Python, so its output is read from `models/fg_make_prob.csv`, which `tools/build_fg_table.py` recovers exactly from published pbp.

**Data sources:** nflverse pbp isn't live; it's rebuilt about once a day after games end.
- `nflverse_stamp()` reads `pbp/timestamp.json` every 60s. `load_pbp(season, stamp)` downloads again only when that stamp changes.
- `load_schedule()` reads the nflverse schedule, which has the ESPN event id, spread and roof.
- `list_games()` gives each game a `source`:
  - `"nflfastR"`: the game is in the published pbp.
  - `"live"`: kickoff has passed, it isn't published yet, and it has an ESPN id. These show 🔴 in the label.
- `load_live_game()` (cached 20s) builds a live game from ESPN plus nflfastR's models.
- The game moves to the official data by itself once nflverse publishes it.
- If the models can't load, EPA/WP stay NaN and the sidebar shows a warning.
- College: `cfb_stamp()` reads the release's `timestamp.json` every 60s; `load_cfb_season()` (`cache_resource`, shared, don't mutate) holds the raw season, `list_cfb_games(season, stamp, today)` lists published games plus today's live ones with week label, AP ranks and conferences (the sidebar filters by conference). The release is rebuilt during game days too, so it can hold games still in progress, frozen at build time: those (`status_type_completed` False) are listed as `source="live"` like unpublished ones, until a build has them finished. A season not published yet still lists its live games. `source == "published"` → `load_cfb_game()` maps one game; `source == "live"` → `load_cfb_live_game()` (cached 20s) runs ESPN's feed through sportsdataverse. A live game moves to the published data by itself once sportsdataverse publishes it, and Follow live / live refresh work as for the NFL. Team colors/logos/nicknames come from `load_cfb_team_meta()`.
- The page reads `team_colors`/`team_logos`/`team_nicks` from `league.team_meta()`, set once after loading.

**Data flow:**
1. `league.load_game()` (`load_pbp`, `load_live_game`, `load_cfb_game` or `load_cfb_live_game`) → `pbp_game` for the selected game
2. `play_timeline(pbp_game)` — elapsed game seconds per play (`3600 - game_seconds_remaining`, `ffill/bfill` for null-clock rows, `cummax` to keep it monotonic)
3. The sidebar's quarter + MM:SS inputs produce `baseline_elapsed`; `cursor_from_elapsed()` turns that into a **play cursor**
4. `revealed = pbp_game.iloc[: cursor_idx + 1]` drives all displayed sections

**Key invariant — spoiler safety:** Every data-driven section must only use `revealed` (the sliced DataFrame), never `pbp_game` directly. The `safety_margin` slider subtracts seconds from `baseline_elapsed` before it is converted to a cursor. The win probability and momentum charts plot each play at its `play_timeline()` position (`_el_min`), so OT lands after regulation, and the x-axis is capped at `elapsed_s / 60` to prevent the chart shape itself from being a spoiler.

**Position model — the play cursor:** viewing position is a *play index*, not a game-seconds scalar. Three session-state keys:

- `_cursor_idx` — the play currently being viewed
- `_cursor_max` — furthest play unlocked; the time bar's slider `max_value`, and therefore the spoiler gate
- `_cursor_key` — `(game_id, qtr_pick, clock_str, safety_margin)`; a change re-seeds both from the clock baseline
- `_cursor_frame` / `_cursor_anchor` — `(game_id, source, len(pbp_game))` and a `(elapsed, rank-within-that-second)` anchor for both cursors. When the frame changes (live plays arrive, or live → official, whose indices differ), `cursor_from_anchor()` carries the position over by game time. It never lands on a later second, or on a later rank within the same second, so a switch can't unlock anything.

An index is used because a clock value cannot address plays individually: plays sharing one `game_seconds_remaining` (penalties, timeouts, two snaps in a second) collapse together. Overtime is worse: its clock restarts *inside* the regulation range (a 2024 OT game carries values like 600, 563, 523), so taken as game seconds every OT play looks earlier than the end of Q4. `play_timeline()` therefore gives OT period n its own slot after regulation, `3600 + 900·(n-1)` to `3600 + 900·n` (the same slot the sidebar's OT + clock input maps to), strictly after the period start. Untimed college OT plays have no clock and are spaced `UNTIMED_OT_PLAY_SECS` apart within their slot. `cummax` keeps the series sorted where a feed's clock steps backwards; it only ever moves a play later. `elapsed_s` is still derived from the cursor, but only for display and the WP x-axis cap — nothing filters on it.

**Viewing position (sidebar):** a single control — quarter + MM:SS game clock, converted to elapsed game seconds (`completed_qtrs * 900 + (900 - remaining)`; OT is `qtr=5`, treated as starting after Q4). Its only job is to seed the cursor; the time bar does the exact syncing from there. `safety_margin` is subtracted from the baseline before the cursor lookup, clamped at 0. For college OT (`league.untimed_ot`) the clock input is hidden: OT seeds at the end of regulation and you step through it. **Full game** (`FULL_GAME`) seeds the cursor at the last play, unlocking everything, for games already watched; its seed key includes `last_idx`, so on a live game it re-seeds as plays arrive.

**Time bar (main panel, between the header metrics and the reveal gate):** an HTML track (`_time_bar_html()`, quarter ticks, fill coloured by possession team, OT segment only once the cursor is in OT) plus an `st.slider` capped at `_cursor_max` and a row of step buttons. The slider deliberately has **no `key=`** so it re-seeds from `_cursor_idx` each rerun and buttons/auto-advance can drive it without a widget-state exception. Only `▶ Next play` and `▶▶ Next drive` raise `_cursor_max`; scrubbing and `⏭ Catch up` never do. On a game still being played they stop short of the feed's edge (`_step_max`): with Follow live at `_cursor_max`, since past it are plays the delay is holding back; otherwise `▶▶ Next drive` is disabled while its drive runs to the end of the feed (`_drive_open`), since that drive is still going and its "end" would be ESPN's newest play. `▶ Next play` still steps one play at a time. Nothing past the cursor is drawn — no scoring marks, no play density, and the caption says "of N *unlocked*", never a total, since the play count alone leaks whether the game ran long.

**Saved position (URL):** `_save_url()` mirrors league, season, game, quarter/clock (or Follow live + delay), Auto-advance and its interval, safety margin and both cursor anchors (`at`/`max` as `elapsed:rank`) into `st.query_params`. A new session (a phone tab backgrounded past the server's disconnected-session TTL, or unloaded and reloaded) reads the URL once into `_url`, uses it only as widget defaults (they must not change mid-session: an unkeyed widget whose default changes starts over), and restores the cursor through the `_cursor_frame` carry-over, so it holds however many live plays arrived meanwhile or a live → official switch. With Follow live, plays past the saved `max` start their delay on restore instead of counting as aired. The Week/Game boxes default to the last game shown (`_game_id`), so a label change (live → official) reselects it.

**Live refresh:** a live game that isn't over reruns every 30s (`live_refresh`) to pull in new plays. That only makes them reachable by the ▶ buttons; it never moves the cursor.

**Follow live:** for a live game that isn't over, a sidebar `🔴 Follow live` toggle replaces the quarter/clock inputs and auto-advance. `_live_seen[game_id]` records the wall time each play position first appeared in the feed; a play is unlocked only once it has been there `live_delay` seconds (slider, default 45s), so a stream running behind ESPN can't be spoiled. Plays already in the feed when you switch it on count as aired, except the newest. It reruns every 10s and, like auto-advance, carries `_cursor_idx` along only when it was at the edge. The ▶ buttons can't pass what has aired; to get ahead, lower the delay.

**Auto-advance:** When `auto=True`, `st_autorefresh` fires and the play cursor section bumps `_cursor_max` by one before anything is drawn, so the play shows on the tick that unlocked it (only when the timer's tick count changed, `_auto_tick`, so a click or a session restored from the URL doesn't reveal a play), carrying `_cursor_idx` with it only if it was already at the edge — so an auto-advancing replay doesn't yank you forward while you're scrubbing back through a drive. The page's timers (auto-advance, Follow live, live refresh) all pass `debounce=False`: the component's default restarts its countdown every time the page redraws it, and the fragments (the ticker every 30s while games are on, the AI polls every 3s) redraw it often enough that a 30–90s timer fired rarely or never.

**Other games ticker:** above the score, `_ticker()` (an `st.fragment`) shows `league.ticker(game_row)` as `ticker_html()` cards while at least one other game is in progress. It reruns on its own every `_TICKER_SECS` (30s) while `scoreboard.busy()`, else every `_TICKER_IDLE_SECS` (5 min), so it stays current on a replay too without rerunning the page. The watched game is never in it: its live score would spoil it. The Spoiler shield's **Hide other games' scores** turns it off. If ESPN can't be read, `load_scoreboard()` returns no games and the ticker doesn't show.

**Collapsed play lists:** Scoring timeline (its label counts the revealed scores), Recent plays (with its filters and pagination) and Current drive (summary caption and play table) are each an `st.expander`: Scoring timeline and Recent plays collapsed by default like Explosive plays, Current drive open; the labels count the revealed plays and the drive's plays.

**Keep screen awake:** a sidebar checkbox (default on) calls `keep_screen_awake()`, which injects a `components.html` script that requests a Screen Wake Lock on `window.parent` (the component iframe itself lacks the permissions-policy grant) and re-acquires it on `visibilitychange`. Requires HTTPS or localhost.

**AI summary league:** `GameContext.league` (`"NFL"`/`"CFB"`) picks the analyst, model name, percentile baseline and OT note in `system_prompt()` (`_LEAGUE`); the NFL prompt text is unchanged. `replay_core.period_label()` gives Q1–Q4, OT, 2OT, … for the page and the summary.

**AI summary and reruns:** a full rerun stops the running script and starts a new one at once (Streamlit's default `runner.fastReruns`), and a live game reruns every 10–30s while a summary takes a minute or more. So nothing in the summary flow waits on one run:
- the button's `on_click` callback records the request in `_summary_requested` (game id) at the start of the click's run; the first run to reach the section with it set builds the `GameContext` and starts the job, so a click whose run is cut short still counts;
- the job (`game_summary.submit()`) runs on a worker thread; `_summary_job` holds its Future, its `Progress`, the viewer's `cursor_anchor` and when it started. While it runs, the fragment shows an `st.status` box with what the agent is doing ("Reading the dashboard", "Thinking it over", or the lookup in progress), the elapsed time, and a checklist of the lookups done;
- `_summary_result()` is an `st.fragment` that, while a job is out, reruns on its own every `_SUMMARY_POLL_SECS` to collect it into `_summary` (or `_summary_error`), then calls `st.rerun()` once to free the button and stop polling. Fragment reruns queue behind full runs instead of cancelling them, so they can't starve slow pages the way full-rerun polling did, and they work on replays where nothing else reruns. The button stays outside the fragment: a fragment click queued behind a slow full run is dropped when the next full rerun replaces it.
- state is written before what it replaces is cleared, so a run cut off in between only leaves work to redo.

**AI summary spoiler gate:** `st.session_state["_summary"]` holds the latest summary with the `cursor_anchor` it was written at. It is shown only for the same game and while that anchor is ≤ the anchor of `_cursor_max`, so re-seeding the clock earlier hides it. Keys come from `_setting()`, which reads `st.secrets` and then the environment.

**UI sections (top to bottom):** other games ticker → header metrics → boxscore → spoiler-free preview (on demand) → AI summary (on demand) → recent plays (Down / Play type / Offense filter pills, `replay_core.filter_plays()` over `PLAY_KINDS` from `play_kind()`, applied before paginating 15/page; a filter change goes back to page 1) → current drive → game management → team stats → situational success rates → line play → tendencies → player leaders → win probability chart.

**Spoiler-free preview** (under the boxscore, `_pv_` session keys): the Matchup page's AI preview of the game being watched. `leagues.pregame(league, season, stamp, game_row)` builds the `MatchupContext` from the regular-season weeks *before* the game's own (all of them for a postseason game, `is_postseason()`), opponent-adjusted: season numbers, `team_snaps()` and `lineup_change()` only over those games, so neither the game nor a later one is in the inputs; the week's injury report and the schedule's betting line (`betting_line()`) are what the game was played under. It returns a `Pregame` (context, matchups, or a `reason` such as week 1 or a team under `SEASON_MIN_PLAYS`). It doesn't depend on the cursor, so there's no spoiler gate; the flow is the game summary's (on_click records `_pv_requested`, the first run to get there builds the context, `game_summary.submit_preview()` runs on a worker thread, `_pregame_result()` is a polling fragment; `_pv_previews` keeps one per (league, season, game)), with the two `matchup_table()`s in an expander. `MATCHUP_LEADERS` and `LINEUP_SHOWN` live in `replay_core` for this and the Matchup page.

**Game management** (after Current drive): each team's win probability and timeouts left, the next snap and end-of-half clock scenarios. `timeouts_left()` reads `home/away_timeouts_remaining` (added to `PBP_COLS`; nflverse and `live_feed` count a timeout on its own row, `cfb_feed` maps the release's `start.*TeamTimeouts`, and `end.*` on timeout rows, to match), 3 each after the half. `next_snap()` estimates the upcoming snap from the last revealed play only (never the next row): offense, down, distance, spot, clock at the whistle and whether it's running (incomplete, spike, penalty, timeout, out of bounds or a college first down inside the `ClockRules` windows, and the two-minute warning stop it), or after a score the receiver's first snap at a touchback; kicks and turnovers end at the text's last "to/at TEAM NN" spot. In the last `SCENARIO_SECS` (6 min) of a half: `three_and_out()` (the offense runs on the downs left, then punts or, inside `FG_RANGE`, kicks; one row per number of timeouts the other team spends) gives when it gets the ball back, `first_downs_to_kneel()` whether the leader can kneel it out, `scores_needed()` what the trailing team needs. `plays_left()` estimates how many snaps a trailing offense gets (for the trailing team with the ball, and in each three-and-out row for the team getting it back): a hurry-up pace from 2024 NFL plays (`HURRY_STOP_SHARE` of plays stop the clock at `HURRY_PLAY_SECS`, the rest add `HURRY_RUNOFF_SECS`), each of its `clock_stops()` (timeouts, plus the two-minute warning while still to come) saving one runoff. The clock constants (`RUN_SECS` + `RUNOFF_SECS` per running-clock snap, `PUNT_SECS`, `KNEEL_SECS`) come from 2024 NFL plays; `tools/validate_game_management.py` checks them. Win probability is nflfastR's model on the estimated next snap and each scenario's 1st & 10 after the kick (`wp_state()` columns, `_`-prefixed so a scenario table can carry them), NFL regulation only; otherwise the last revealed `home_wp`. **Hide win probability chart** hides the numbers here too.

**Season stats (`replay_core`, the Season stats page):** `team_stats()` is built from `_team_col(plays, team, side)` (side `defteam` = what a defense allowed) and `situational_success_rate()` from `situational_table()`, so the season tables use the replay's definitions. `season_team_table(pbp, side)`: one row per team, `SEASON_COLS` (Games, `TEAM_STAT_ROWS`, `LINE_ROWS`; a defense drops its own penalties), counts in `SEASON_PER_GAME` divided by games. `season_ranks()` gives each cell's 0–100 percentile within its column (100 = best; `season_lower_is_better(side)` flips Team stats' and Line play's lower-is-better sets, and for a defense every other column); `SEASON_VOLUME` columns aren't colored. `season_players()` / `season_defenders()` run `top_players()` / `top_defenders()` for every team (a traded player has a row per team), `season_player_distributions()` / `season_situational_distributions()` (team-seasons) are their color baselines. `_top_seconds()` groups by game too, since drive numbers restart each game. Data: `League.season_pbp(season, stamp)` (finished published games plus `postseason`; NFL from the schedule's `game_type`, college from `seasonType`, games with an FBS team) and `League.season_teams()` (the ranked teams → group: nflverse divisions; FBS teams → conference), `leagues.season_plays()` filters, `leagues.season_tables(..., adjust)` / `season_tendencies()` cache the tables per selection (`situational_defense` is what each defense allowed by situation, adjusted with the offenses' strengths); the team tables use every team in the plays (FCS opponents too) and keep only the ranked ones at the end. **Opponent adjustment** (`opponent_adjust(off, def_, season_games(pbp))`, like SRS): an offense's season value less the average strength of the defenses it faced, a defense's less that of the offenses it faced, iterated (up to `ADJUST_MAX_PASSES`, to `ADJUST_TOL`); a strength is a team's adjusted value minus the league mean, shrunk by games / (games + `SHRINK_GAMES`) so a team seen once or twice can't swing its opponents. The league mean is kept. `SEASON_ADJUST_SKIP` (volumes and time of possession, a team's own penalties, aDoT) stays as played. Being additive, it can push a value with few plays behind it past its stat's range, so `_season_tables()` passes every adjusted table (teams, situational, players) through `possible_values()`: `SEASON_RATES` kept within 0–1, `SEASON_PERCENTS` (situational and player SR%) within 0–100, `SEASON_COUNTS` (Rush+Comp, Turnovers, Lost Poss.) at 0 or more, and in team tables Rush+Comp between the row's Rush Plays and Plays and QB Hit % at least Sack %; EPA and yards have no bounds. `tools/validate_matchup.py` applies it too. The same runs on `season_situational()` (teams × (situation, metric); `situational_distributions_from()` makes its color baselines), and `adjust_players()` takes each player's SR%/EPA/play less the play-weighted strength of the defenses he faced (`PLAYER_ADJUST` maps them to team columns); counts, aDOT and defenders stay as played. **Filters:** `leagues.season_plays(..., play_filter)` filters whole games first, adds `_margin` (`pre_play_margin()`: home − away before the snap, from the previous row's totals, which are after the play) and then `filter_plays_by()`: quarters (`qtr` capped at `OT_QTR`), garbage time (`offense_wp()` outside [x, 1 − x]; NaN WP kept) and clutch (`qtr == 4` with ≤ minutes left, or OT, and |margin| ≤ points). The venue is a team-side filter: `season_team_table(..., venue)` / `season_situational(..., venue)` keep each team's own home or away games, players and defenders come from `venue_plays()`; with Opponent-adjusted on, strengths come from the all-venue tables and `apply_strength()` adjusts the venue tables over `venue_games()`. `play_share` (scrimmage plays kept ÷ the unfiltered selection's) scales the default player minimums. A college season takes about a minute the first time.

**Matchup (`replay_core`, the Matchup page):** over the season tables (`season_qualified()`), `matchup_table(off, def_, offense, defense)`: per `MATCHUP_ROWS` stat (`matchup_stats()` drops what the league's data can't fill: college's QB Hit % and CPOE; ED SR, CPOE and RYOE/att are rows like the rest, so the page and the preview agent get them, and `MATCHUP_PROMPT` defines them) the offense's value and place (`season_places()`, which `season_rank_label()` also uses), what the defense allowed and its place, League (both tables' mean), Edge (the offense's `season_ranks()` percentile less the defense's, `season_lower_is_better()` per side; none for `MATCHUP_STYLE`: volumes and aDoT) and Proj. (league + `PROJ_SHRINK` × the offense's and the defense's distances from it; 0.5 from `tools/validate_matchup.py`, where 2024–25 games landed 0.23–0.67 of the way from the average to the full sum, turnovers less). `head_to_head(table, away, home, side)`: the two teams' rows of one table, Δ = away − home. `situational_matchup(off_sit, def_sit, offense, defense, plays)`: Pass/Rush SR% per `MATCHUP_SITUATIONS`, counts from `plays` (`_situation_counts()`, season totals), no edge unless both sides have `SITUATION_MIN_PLAYS` (its rates come in already within 0–100%, from `possible_values()`). `edge_label()` writes an edge as "KC 25" ("Even" under `EDGE_EVEN`) for the page and the preview alike. `_`-prefixed columns carry percentiles and counts for the stylers.

**Availability (`replay_core`, the Matchup page and the Season stats Team tab):** NFL only, linked by nflverse's gsis id. `PBP_COLS` carries `passer/rusher/receiver_player_id` (NaN for live NFL and college games) so `player_ids()` can map the play-by-play's names ("D.Maye", "Bi.Robinson") to ids; nflverse's own short names collide (two "B.Robinson" on ATL), so they're only a fallback, for defenders, in `status_by_name()`. `team_snaps(snaps, team, games)`: per player G, then Off / Def / ST snaps and their share of the team's (`SNAP_PHASES`); a team's snaps in a game are read off its fullest-playing player (snaps ÷ share; exact in 99.5% of games on offense, the fullest special-teamer plays 61%+). `injury_report(injuries, team, week, snaps, starters)`: the week's listed players, Status (`INJURY_STATUSES`, "" before the final report), Injury, Practice (`PRACTICE`), Snaps (share in the phase he plays most, "89% O"), Starter; `availability_summary()` by `UNITS` / `UNIT_ORDER`: Out or doubtful (`LIKELY_OUT`), Questionable and Snaps out, the likely-out players' shares of the unit's own phase (`UNIT_PHASE`, so a DB's special-teams snaps don't count as defense). `views.style_injury_report()` tints Status (`STATUS_TINTS`), `status_badge()` (`STATUS_BADGES`), `style_snap_table()`. **Lineup vs the season numbers:** `lineup_change(snaps, injuries, roster, team, week, games)` measures a lineup against the players behind the season numbers (the snap counts over `games`), not against a full-strength team: per player in his unit's phase, Was (share of those games' snaps), Now (0 if gone; if back, his share in the games he played) and Change, with Why: Out or Doubtful on the week's report, or a roster status outside `AVAILABLE_ROSTER` (`ROSTER_WHY`: reserve lists, which drop off the report, releases, trades; the roster is the week's or the team's latest before it), or "Back" for one Out or off the roster in one of those weeks. `lineup_groups(change, part)` sums it by `LINEUP_GROUPS` (QB, OL, Skill, Front, DB) in full-time players: net, `"lost"` or `"back"`. `lineup_adjustment(offense_change, defense_change)` moves Proj. by `LINEUP_EFFECTS` (EPA/play, Pass EPA/play, Pass SR) per full-time player gone: the offense's own QB/OL/Skill, the defense's Front/DB. `tools/validate_injuries.py` fits them (2016–2025, weeks 4+, opponent-adjusted Proj.) and tests each form a season at a time out of sample; players gone only, no intercept, is the page's: EPA/play RMSE 0.1839 → 0.1814 (0.1946 → 0.1828 with a QB change), winner picks 61.5% → 63.1% (betting line 67.8%). Players back aren't counted (no measurable effect), nor run EPA or sack rate (no gain). `views.style_lineup_groups()` / `style_lineup_change()`.

**Stat tables:**
- `boxscore()` — quarter-by-quarter score via cumulative score diffs; every OT period goes in the one OT column
- **Snaps a penalty wiped out:** a pass or run nullified by a penalty (`no_play`, on a down) counts in EPA/play and success rate, the team's (Team stats, situational, season tables, `game_epa()`, the summary's defense table) and the named players' (`_player_plays()`), as rbsdm.com counts them; its EPA is the penalty's. `nullified_snaps()` finds them by the names every source puts on those rows (a passer: a pass; only a rusher: a run). Plays, yards, CMP%, 1st Down %, line play, tendencies and the leaders' counts stay real plays only (`_REAL_PLAY_COLS` are blanked on those rows).
- **ED SR** (Team stats, after Rush SR): early-down success rate, the share of 1st- and 2nd-down passes and runs (the ones a penalty wiped out included) with EPA > 0, `_early_down_sr()`; a rate in `SEASON_RATES`, so it reaches the season tables and the summary too.
- **Over expected:** CPOE is nflverse's per-pass `cpoe` (percentage points; NaN for live NFL and college games, shown "—"), averaged by `_cpoe()`. RYOE is rushing yards over expected per designed run (`_ryoe()`): rushing yards less `xrush_yards`, the league's average designed run from the same down × distance × field-position cell (`XRUSH_DIST_BINS` / `XRUSH_FIELD_BINS`, cells under `XRUSH_MIN_RUNS` fall back to down × distance). `fit_expected_rush()` builds the table, `tools/build_xrush_table.py` writes it to `models/xrush_yards.csv` per league (NFL 2019–2025, college 2023–2025; R² ≈ 0.02 per run, the same out of sample), and `leagues.with_xrush()` adds the column wherever play-by-play is loaded (`nflverse_pbp()`, the live loaders, the college game/season/baseline loaders). Team stats carries both as `CPOE` and `RYOE/att` (so the season tables, Season stats' Efficiency view and the summary do too), Situational success as `Pass CPOE` / `Rush RYOE` (no play counts in those cells).
- `team_stats()` — advanced EPA-based stats, returned as a transposed DataFrame (stat names as index, team abbrs as columns); styled by `style_stat_table()`. The game totals (`GAME_TOTAL_ROWS`: yards, plays, Rush+Comp, turnovers, Lost Poss., TOP) get a percentile only once `game_over(revealed)` (the last revealed row is END GAME): against whole games a partial total looks low, so until then the table leaves them uncolored and `stat_percentiles(..., final=)` leaves the summary's pct blank. Percentiles come from `leagues.stat_baselines(league, season)` / `leagues.situational_baselines(league, season)`: the 3 prior NFL seasons, or last college season's FBS-vs-FBS games (`_cfb_baseline_pbp`); `league.baseline_label` names them in the captions
- `situational_success_rate()` — pass/rush SR% and EPA/play by down group × distance (`SR_SITUATIONS`); the section's **Early/late subtotals** toggle passes `subtotals=True`, which appends bold `Early · Total` / `Late · Total` rows (`SR_SUBTOTALS`, every distance), with their own baselines in `situational_distributions()`
- **Series success** and **By play type** (under Situational success rates): `series_success()` gives each team's Series Conversion Rate (SCR), the share of series starting on 1st down (`series_list()`: a series runs to the next 1st down or the end of the drive) that earn a first down or the offense's own touchdown, over every series and by the first snap (`SERIES_ROWS`; nullified snaps count as what they were, pre-snap flags are skipped, kneel-opened series and the last series while it's still going are left out). `play_splits()` gives one team's EPA/play, SR, 1st% and Plays per `PLAY_SPLITS` row (all / rush / pass, overall, early and late downs); EPA and SR count snaps a penalty wiped out, 1st% real plays only. Colors: percentile vs team-games in the baseline, `leagues.series_baselines()` (`series_distributions()`, `play_split_distributions()`); styled by `style_series_table()` / `style_play_splits()`
- `line_play_stats()` — the **Line play** table (after Situational success rates), per offense: dropbacks, Sack %, QB Hit % (hits include sacks; dropped where `missing_stats` has "QB Hits", i.e. college), designed runs (no kneels, no scrambles), Stuff % (≤ 0 yds), Explosive Run % (≥ `EXPLOSIVE_RUN_YDS`), snaps and OL Penalty % (the offense's own holding, false start and ineligible-downfield flags per pass/run/no-play snap, matched in the text by `OL_PENALTY`). Downs only, so two-point tries are out. Percentiles from `leagues.line_baselines()` (`line_play_distributions()`, same baseline seasons), flipped for `LINE_LOWER_IS_BETTER`; styled by `style_line_table()`
- `run_tendencies()` / `pass_tendencies()` — the **Tendencies** section (after Line play), per offense and filtered by a Downs control (`TENDENCY_DOWNS`: all, early, late): designed runs (`_designed_runs()`, shared with Line play) by gap (`RUN_GAPS`, LE … Mid … RE) or, where `league.run_gaps` is off (college), by side; passes thrown (no sacks or spikes) by depth × side, depth in air yards (`PASS_BANDS`: Deep 20+, Inter 10–19, Short 0–9, Behind LOS) unless the game has none (`has_air_yards()` false: live NFL), then the text's short/deep (`PASS_DEPTHS`). Each cell has plays, share, yds/play, SR and EPA/play (passes add Cmp% and aDOT, which live NFL games lack). Plays with no direction in their text are left out. `run_tendency_figure()` draws bars (share, colored by EPA/play, a grey dash at the league's share), `pass_tendency_figure()` a deep-over-short grid; the league numbers (hover and dashes) are `leagues.tendency_baselines()` (`tendency_baselines()`, the same baseline seasons, league-wide; per downs option a dict of `runs`, `air` and `text` passes)
- `top_players()` / `top_defenders()` — per-team passing/rushing/receiving leaders sorted by yards, with Total EPA (the sum over the same plays as EPA/play, uncolored; `adjust_players()` takes it less each defense's strength once per play against it) (their rates, `PLAYER_RATE_COLS`: SR%, aDOT, EPA/play, colored by `style_player_table()` by percentile vs `leagues.player_baselines()`, i.e. `player_distributions()` over the baseline's player-games with at least `PLAYER_MIN_PLAYS` dropbacks/carries/targets; players below that stay plain; `_player_plays()` is the play filter both share), and defensive leaders (Tackles = solo + assists, each assist a full tackle, as the NFL and NCAA total them; half sacks and half TFLs count 0.5); `drop=missing_stats` (`league.missing_stats(revealed)`) removes columns this game's data doesn't have
- `top_plays_wpa()` — the **Top plays by win probability added** table, with each play's EPA next to its WPA
- `drive_chart()` — one row per drive; above it, `drive_field_figure()` draws each drive from `drive_field_spots()` as an arrow on a field (home drives left → right from its own end zone on the left, away right → left; end zones carry team colors, logo and nickname). Each arrow is split into one segment per play (line of scrimmage to the next play's spot), coloured by `_play_category()` — pass or run on 1st/2nd down, pass or run on 3rd/4th down, or accepted penalty (`no_play` with `penalty == 1`); scrambles count as runs and sacks as passes, following nflfastR's `play_type`. A tick marks every snap so no-gain plays still show, and hovering a tick shows that play. The start/end markers keep the team color. Hover shows each drive's time of possession, measured to the next drive's start within the same half, as nflfastR does. The field graph is always shown; the table sits in an expander, collapsed by default. The last revealed drive is labelled "In progress" unless the last revealed row is an END marker.
